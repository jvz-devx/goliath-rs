### Packet observer

`scripts/e17_wire.py` forwards loopback TCP with one selector thread. Observers
sit before Meridian and before each backend. The decoder follows login,
compression, configuration and Play framing, including incomplete TCP reads.
It matches every unchanged serverbound position packet by player name and exact
decoded payload. Repeated positions use FIFO matching. No tail is trimmed.

Front-read to backend-read latency includes both observer forwarding queues,
Meridian queues and local TCP scheduling. It is a conservative proxy-path
measurement for serverbound movement, not a measurement of all packet types or
the clientbound path. The observer's process CPU is reported separately in the
pilots. Its traffic accounting separates each backend's real-or-held sessions
and synthetic readers. It cannot attribute backend tick time by itself.

Eleven observer and adapter tests pass, including a real two-observer loopback route, partial
frames, compressed packet identity, status probes, FIFO matching and a retained
100 ms tail, session-kind rejection, explicit external load preservation and
lossless repeated tick drains. The seven unchanged E11 tool tests pass too.

E11's old four-server scheduling shortcut used its 200-bot reference to replace
explicit loads, including external configurations. External runs now preserve
the requested load. Plain E11 scheduling is unchanged. Long measurements drain
the same raw tick buffer every 60 seconds, retaining all samples and dropped
counts. This collection change applies to plain and cluster runs alike and does
not change acceptance. It prevents a 30-minute soak overflowing the 8,192-tick
engine buffer. The current W1 process had already loaded the original collection
code and used its original one-minute windows.

The observer itself previously used the shared Darwin ephemeral source-port
range, 49,152 through 65,535. Its failed 200-client run hit error 49 while
opening a new backend tap. It then closed every observed connection, so its
latency tail is invalid and remains a failed result. Observer-created outbound
sockets now bind transient source ports in 20,000 through 39,999, skip occupied
ports and reuse eligible tuples. No host setting or interface is changed.
A failed new connection now marks latency invalid without closing unrelated
sessions. Unit tests verify the source-port range and failure isolation through
real loopback sockets. Live 200-client validation of this observer repair is
still pending. It cannot fix Meridian's own control-connection churn.
